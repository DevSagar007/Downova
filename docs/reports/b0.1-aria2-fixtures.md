## Findings to carry into B0.4 / ADR 0003

1. **Truncation is classified as `RANGE_UNSUPPORTED`.** aria2 reports code 8 because it would need to resume the cut body, and the fixture server offers no ranges. A user-facing message should rather say "connection ended early; server does not allow resuming". COR-03/CORE-11 need a finer classification, possibly by combining the code with observed length.
2. **Correction (B0.4):** the statement below is wrong. The archive contains a `LICENSE.OpenSSL` file, but the binary does not link OpenSSL: it uses WinTLS (SChannel). See the [B0.4 report](b0.4-http-correctness.md#tls-backend-and-bundled-libraries). Original text, kept for the record: **Pinned Windows build bundles OpenSSL** (`LICENSE.OpenSSL` in the archive; a 2023 release). The research says not to bundle old TLS libraries blindly (§15.2). The bundled OpenSSL version must be checked and recorded, then accepted or replaced (custom build, or aria2 with WinTLS) before shipping (REL-05).
3. **Upstream publishes no digest** for the release assets (GitHub API `digest: null`). The pin is trust-on-first-use, cross-checked against the API size.
4. **Not covered yet (B0.4):**
   - changed resource with the same length;
   - changed, weak or missing ETag;
   - 416;
   - Content-Encoding changes;
   - unknown length;
   - zero-byte files;
   - 429/503 with Retry-After;
   - 401/403/410;
   - redirects;
   - `filename*`;
   - TLS;
   - crash or kill during transfer.

   Capabilities therefore stay `unverified` or `unsupported`; none is promoted to `supported`.
5. **macOS/Linux:** not run locally. CI uses brew and apt aria2 (Ubuntu 22.04 ships 1.36.0, which is not the pin). CI has not run yet.
