## 1. User-visible functionality

### History retention (B2.12, CORE-10)

- **Options → History.** "Keep finished downloads in the list": Forever (default and recommended), 7, 30 or 90
  days, or 1 year.
  - **Apply** shows the service's exact count ("2 of 3 finished downloads … will leave the list now") and that files
    stay on disk, then asks.
  - **Clean now** applies the saved period the same way.
  - Focus returns to the opening button.
- **The service owns retention.** These hold whether or not a window is open:
  - a durable finish time (migration 7), stamped once and never moved by renames, queue moves or settings;
  - legacy finished rows count from the upgrade;
  - bounded sweeps at startup and every minute, through the same durable removal as Remove from list;
  - open windows update through `job_removed` events;
  - same-key replays still answer.
  - Never: deleting downloaded or partial files, backend discard, opening anything.
- **Compatibility.** `history.v1.*` is separate from `settings.v1`, so a client that saves destination settings
  cannot reset retention.
- **CLI:** `dm history`, `history-set <DAYS|forever>`, `history-preview`, `history-clean`.

### Automatic capture (B2.13, BRW-03/04/06, E02)

- **Opt-in.** Capture is off by default, turned on from the extension's options page.
  - Turning it on requests the optional `downloads` and `webRequest` permissions.
  - Each site the user adds requests that site's origins.
  - Turning it off or removing a site gives the permissions back.
- **Explicit hand-off.** The context-menu hand-off is unchanged and works without any capture permission.
- **Options page:**
  - status of the permissions and of Downova;
  - a "What is captured" explanation;
  - sites and exclusions;
  - file-type, MIME and minimum-size filters;
  - a bounded recent-activity list with actionable reasons, in English and Bangla.
- **Popup:** a capture summary and a link to the settings.
- **When the browser starts a download on an allowed site:**
  1. The extension waits (at most 5 s) for the browser's file name and danger verdict and for request evidence.
  2. It decides.
  3. It records the capture and its idempotency key.
  4. It sends the link to Downova.
  5. It cancels the browser's copy only after Downova accepted it and a recheck passes.

  The activity list says what happened to both copies.

### Accessibility (B2.14)

- **Automated WCAG 2.2 AA contrast** of the desktop tokens and the extension colours in light and dark: 43 pairs,
  all pass.
- **Focus restoration** after the History confirmation (with a test). The new dialogs and controls have labels,
  and unavailable actions give text reasons.
- **Extension:** forced-colors and reduced-motion rules on the options page. The activity live region announces
  new entries only, not every state change.
- **Browser preview:** Options at 320 CSS px (the WCAG reflow width) in Bangla and dark: no horizontal overflow and
  no clipped text.

## 3. Supported automatic-capture cases and browser fallback

| Download | Outcome | Evidence |
|---|---|---|
| Plain public GET from an allowed site: no cookies or credentials, 200, every redirect allowed, browser verdict safe, not executable, passes the filters | **Captured**: accepted by Downova, then the browser copy cancelled | C1 real Chrome/Edge; unit |
| The same, with a duplicate event or a worker stopped mid-capture | One job (same key) | C2 real Chrome/Edge; unit |
| POST / form export | Browser (`not_get`) | C3 real; unit |
| `blob:` | Browser (no record) | C4 real |
| `data:` | Browser | unit |
| Cookies or Authorization sent | Browser (`sent_cookies` / `sent_credentials`) | C5 real; unit |
| Redirect outside the sites; ambiguous or missing request evidence | Browser | unit |
| Browser warning, executable or installer | Browser | unit |
| Started by another extension | Ignored | unit |
| Private window | Browser (capture not available) | manifest + unit |
| Unknown size or MIME with a restrictive filter | Browser | unit |
| Downova missing, down, rejecting, malformed or timing out | Browser keeps downloading; record failed or uncertain | unit |
| Browser finishes first, or the user cancels it | Reported; never cancelled again | unit |
| Capture disabled or permission revoked during the hand-off | Browser copy kept | unit |

**Not claimed:**
- universal takeover;
- authenticated or session downloads;
- single-use detection beyond the user's site list;
- exactly one copy across both applications after an uncertain acknowledgement. The service still creates at
  most one job.

## 4. Remaining privacy, human-test and release gaps

- **BRW-10:** private-window capture is not offered. The service keeps durable history and idempotency records, and
  Chrome split mode does not isolate `storage.local`, so an ephemeral policy would be needed end to end.
- **Permission prompts:** the real browser prompts for the optional permissions were not exercised. The e2e build
  pre-grants them for the local fixture hosts, and the prompts need a human check.
- **Human checks not run:** right-click, tray, OS logout/sleep/reboot, screen readers.
- **Existing popup strings** (the explicit hand-off) are still English only. The new capture copy is English and
  Bangla.
- **E02:** Opera not tested.
- **UI-02:** the human audit before beta is not done.
- **Retention clock:** retention follows the wall clock. A clock moved forward by hand can make entries due early
  (list entries only).
- **Release:** signing and notarisation remain out of scope.
