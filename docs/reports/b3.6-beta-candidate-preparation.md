## 2. What changed

**Update and installer lifecycle (REL-01, ADV09):**
- **One build version** (`dm_domain::BUILD_VERSION`):
  - `package.mjs --app-version` builds a fixture at another version (fixture builds only);
  - after every build, `package.mjs` checks `--version` of each staged binary and each binary in the MSI, plus
    the installer names, and refuses a package that disagrees;
  - `dm-service --version` is new.
- **No silent attachment:** the desktop refuses a running service of another build version and says a different
  version is running.
- **The installer stops only its own service:**
  - the service records its executable in `run/endpoint.json`;
  - `dm shutdown --only-from DIR` stops it with state kept, but only from that folder;
  - the NSIS pre-install and pre-uninstall hooks call it.
  - Found by reading the pinned Tauri NSIS template: the installer checked only `dm-desktop.exe`, while the
    service outlives the window.
- **Restore gets you back to work:** after a confirmed restore, the shell now starts the service on the restored
  data. Before, the window only re-probed, so the user was left at "not running".
- **A manual pause survives a restart without saved progress.** Found by the update journey: such a download came
  back as failed, "interrupted … add the link again", even after a clean stop. It now stays paused and starts
  afresh when resumed. This amends ADR 0012 §5 (ADR 0031).
- **B3.5 contract check:** `PrepareUpdateParams` examples now apply the schema's version pattern.
- **Packaging:**
  - stale bundles from an earlier build are no longer collected (`target/release/bundle` is cleared first);
  - fixture labels carry the version;
  - `build-info.json` records `build_kind`, `version`, `components` and the notices summary.
- **Tooling:**
  - `scripts/update/build-fixture-pair.mjs`: two fixture versions, one disposable key, deleted afterwards;
  - `scripts/acceptance/update-journey.mjs`: the isolated A→B journey;
  - `verifier-fixture.mjs --release`.

**Notices (REL-03):**
- the inventory generator and its `verify` check;
- `third_party/notices/` with verbatim texts;
- `THIRD-PARTY-NOTICES.txt` bundled as a Tauri resource and placed next to the packages;
- Help → Third-party notices… (offline, English/Bangla).

**Acceptance kit and support (REL-02):**
- **`build-kit.mjs` collected only one-letter row IDs.** So since B3.4/B3.5, FX1–FX4 and UP1–UP4 never reached
  `RESULTS.csv`. It now takes one to three letters.
- It refuses update-fixture packages, and records version, components and notices.
- New checklist rows IL1–IL6 (installer lifecycle, NSIS and MSI separately) and TN1 (notices).

**UI-01:** see §5.

## 4. Dependency notices and the license audit (REL-03)

**How it is built.**
- `scripts/notices/generate-notices.mjs` reads `cargo metadata --locked --filter-platform` for
  `x86_64-pc-windows-msvc`, `aarch64-apple-darwin` and `x86_64-unknown-linux-gnu`.
- It walks normal dependency edges from the four shipped binaries (`dm-desktop`, `dm-service`, `dm`,
  `dm-browser-host`).
- Procedural macros and build dependencies, with what they pull in, are **build-only**. Test-only packages and
  packages of other targets are **not distributed**.
- Web code: the desktop's production npm closure. The extension has no runtime dependencies.
- Other components: `third_party/notices/manifest.json` (verbatim texts beside it).
- Texts are the top-level LICENSE/COPYING/NOTICE files of each published package. Nothing is guessed.
- The result is checked into `apps/desktop/src/generated/third-party.notices.json`, and `pnpm verify` fails
  while it is stale.

**Result** (inputs: Cargo.lock and pnpm-lock.yaml of this tree):

| | Count |
|---|---|
| Distributed components | 385: 4 non-package components (Rust std, NSIS, nsis_tauri_utils, WiX resources), 376 Rust crates, 5 npm packages (`@tauri-apps/api`, `lucide-react`, `react`, `react-dom`, `scheduler`) |
| Of these, target-specific | 157 (for example `windows-*` and `webview2-com*` on Windows only, `objc2*` on macOS only) |
| With unresolved metadata | 24 |
| Excluded | 106 (build-only, or not distributed) |
| Distinct license texts | 239 |

**License expressions found among distributed components:**
- **Permissive:**
  - MIT and/or Apache-2.0 in their spellings, including `MIT/Apache-2.0`: the large majority;
  - BSD-3-Clause, ISC, Zlib, 0BSD, Unlicense OR MIT, CC0-1.0 OR MIT-0 OR Apache-2.0;
  - Apache-2.0 WITH LLVM-exception (dual or triple licensed).
- **Unicode-3.0:** 15 ICU-family crates, plus `(MIT OR Apache-2.0) AND Unicode-3.0`.
- **MPL-2.0:** 4 crates (for example `selectors`). This is file-level copyleft: the source of those files must
  stay available. Their unmodified published sources satisfy this, but the offer belongs in the release notice.
- **MS-RL:** the WiX UI resources in the MSI. **Zlib/bzip2/CPL-1.0:** NSIS.
- **No GPL or LGPL component is distributed.** aria2 (GPL-2.0-or-later) is **not bundled** (ADR 0005). It stays
  an optional external sidecar, listed under "Used but not included".

**Unresolved (kept explicit, never filled in):**
- **No license text in the published crate:**
  - 20 crates, for example `webview2-com`, `webview2-com-sys`, `objc2`, `objc2-*`, `block2`, `dispatch2`,
    `dlopen2`, `selectors`, `alloc-stdlib`, `libappindicator-sys`, `mac-notification-sys`;
  - their license expression is known, but the copyright line an MIT/BSD notice needs is not in the package.
- **`nsis_tauri_utils`:** neither version nor license is recorded in the binary.
- **Rust standard library:** its per-file and out-of-tree notices (`COPYRIGHT-library.html`, about 1.5 MB, with
  Unicode-3.0 data) are not yet bundled.
- **NSIS:** which compression module the Tauri script selects is not confirmed.
- **WiX:** which extension resources end up in the MSI is not confirmed.
- **`webview2-com-sys`:** it embeds Microsoft's WebView2 loader library. The SDK license terms for that part need
  confirming.
- The desktop web bundle may also contain small bundler helpers (Vite/Rollup runtime code), which are not
  inventoried.

**For the project-license decision (ADR 0001, maintainer):**
- Nothing distributed forces a copyleft project license. MPL-2.0 is file-level, and MS-RL covers only the WiX
  resources.
- With aria2 unbundled, a permissive license (for example MIT OR Apache-2.0, matching most of the ecosystem) or a
  copyleft one are both possible. Bundling aria2 later would require GPL-2.0-or-later compliance for that
  component.
- **Before REL-03 can be verified:**
  - choose the license;
  - resolve the 24 items above (obtain the copyright notices from the upstream repositories at the exact tags, or
    replace the crates);
  - bundle the Rust std notice file;
  - add the MPL source offer.
