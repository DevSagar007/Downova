## Behaviour (backend `http`)

| Situation | Outcome |
|---|---|
| Known size does not fit (free < remaining + 64 MiB) | No body byte is written. Job `queued` + `disk_unavailable`, error `DISK_FULL` (retryable, `free_disk_space`, amounts in the message). It starts once space is back |
| Unknown length runs out of space | Stopped at the next sync window; nothing resumable, so it starts afresh once space is back (never resumed without a validator) |
| Real `ENOSPC` while writing or syncing (single or segmented) | Last durable checkpoint committed, partial kept, job waits; continues from the checkpoint with validated ranges (exact SHA-256) |
| A waiting job and a service restart | Checkpoint kept; the restored job continues from it (or waits again if space is still short) |
| User pauses a waiting job | Stays paused when space returns; resume returns it to the waiting/continuing path |
| Cancel a waiting job | Final; restored space does not revive it |
| Free space cannot be determined | Advisory pass, reported once on stderr; the `ENOSPC` path still protects the job |
| Destination folder or drive missing | `volume_missing` blocker, `VOLUME_MISSING`, `reconnect_volume`; continues when it is back |
| Finalization copy fallback does not fit (or `ENOSPC` half-way) | Only the partial copy is removed. Journal entry stays at `verified`, staging kept, job `verifying` + `disk_unavailable`. Placed once space is back, also across a hard kill |
| aria2 backend | Unchanged: disk full fails the job explicitly (no durable resume, no unvalidated control-file resume) |

Policy: margin 64 MiB. Checks run before the first body byte, at every durable sync (≥ every 1 s or 4 MiB), before the
copy fallback, and every 2 s while a job waits. They are **advisory**: no reservation, no capacity promise.

## Limitations and unverified cases

- **No real disk was filled.** `ENOSPC` is injected (debug builds) and free space comes from a test probe. Whether every
  OS reports a full disk as `StorageFull`/`QuotaExceeded` is assumed from the standard library mapping, not observed.
- The checks are advisory snapshots with no reservations across concurrent jobs.
- The 64 MiB margin is fixed (no setting yet).
- Unknown-length and validator-less downloads restart from zero after a disk-full stop.
- If SQLite cannot commit on a full disk, the failure is reported on stderr and the last committed state stays
  authoritative. That case is reasoned about, not fault-tested at the database level.
- Removable-volume identity (the same drive returning) is ADV05 advanced, B4. `volume_missing` here only means the
  folder is absent.
- aria2 keeps terminal disk-full failure. The UI does not show blockers yet (B2).

## Reproduction (debug build)

1. Build:

   ```bash
   cargo build -p dm-service -p dm-cli
   ```

2. `echo 0 > /tmp/dv-free`, then start the service:

   ```bash
   DOWNOVA_TEST_FREE_SPACE_FILE=/tmp/dv-free DOWNOVA_CHECKPOINT_TRACE=/tmp/dv/trace.jsonl target/debug/dm-service --data-dir /tmp/dv --download-dir /tmp/dv-dl
   ```

3. Run `target/debug/dm --data-dir /tmp/dv add <URL>`, then `… list`. The job waits with `disk_unavailable` and a
   `DISK_FULL` reason.
4. `echo 1000000000000 > /tmp/dv-free`. Within about 2 s the job starts and completes.
5. Variations:
   - add `DOWNOVA_FAULT=enospc_write` and keep the probe high: a real write error stops the job after its first
     checkpoint, and it continues from that checkpoint;
   - `DOWNOVA_FAULT=no_hard_links,enospc_copy` exercises the copy fallback failing once.
