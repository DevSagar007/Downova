## Rules

### Precedence of the final name

1. A valid `filename*` (RFC 8187).
2. `filename` (RFC 6266).
3. The final response URL's last path segment (after redirects; never the query).
4. The requested URL's last path segment.
5. `download`.

A candidate that is empty after sanitizing falls through to the next one.

### Parsing

| Input | Result |
|---|---|
| `filename="a;b.txt"`, `filename="say \"hi\".txt"` | `a;b.txt`, `say "hi".txt` (quoted `;` is data, `\` escapes) |
| `FileName = "x"` | parameter names are case-insensitive, whitespace allowed |
| `filename=a; filename=b` (or `filename*` twice) | that parameter is ignored entirely; the others still count |
| unterminated quote, or text after a closing quote | parsing stops; nothing from that point on is used |
| `filename*=UTF-8''%E0%A6%AC…`, `iso-8859-1'de'f%FCr.txt` | decoded |
| `filename*` with another charset, `%2` or invalid UTF-8 | discarded; `filename` is used |
| `filename="%41.txt"` | `%41.txt` (never percent- or RFC 2047-decoded) |
| a non-UTF-8 field value | read as ISO-8859-1 |
| a field longer than 4 KiB | dropped |

### Sanitizing

- NFC normalization. Bangla, other scripts and emoji are kept; ZWJ and ZWNJ are kept.
- `/ \ < > : " | ? *` and control characters become `_`.
- Bidirectional overrides and isolates, zero-width space, word joiner and BOM are removed.
- Leading dots and spaces are removed; so are trailing dots and spaces.
- `CON`, `PRN`, `AUX`, `NUL`, `CONIN$`, `CONOUT$`, `COM0–9`, `LPT0–9`, `COM¹²³` and `LPT¹²³` (any case, any extension)
  get a `_` prefix.
- A name ending in `.downova-part` or `.aria2` gets a `_` appended.

### Limits

| | Windows | Linux and macOS |
|---|---|---|
| Component limit | 255 UTF-16 units | 255 UTF-8 bytes |
| Name budget (minus the 24-unit reserve for ` (xxxxxxxx)` + `.downova-part`) | 231 units | 231 bytes |
| Path target | 259 units (`MAX_PATH`) | 4095 bytes |
| Floor when the folder is deep | 32 units | 32 bytes |

- Truncation keeps whole grapheme clusters and an extension of up to 16 units.
- A Bangla letter costs 1 UTF-16 unit but 3 UTF-8 bytes, so a Windows name keeps about three times as many Bangla
  letters as a Linux name.
- These are documented conservative values, not universal constants. A volume with a smaller limit refuses the file,
  which is reported as `DESTINATION_UNWRITABLE`.

### Collisions

A candidate is free only when all of the following hold:
- no directory entry of that name exists;
- no other job in the folder uses it as a final or staging name (NFC, case-insensitive);
- no `.downova-part` or `.aria2` file of that name exists, except the job's own partial file.

Otherwise the name gets ` (n)` before the extension. Placement never overwrites (ADR 0008).

### Identity, freeze point and compatibility

- **Staging name.** Fixed at acceptance. The partial file, checkpoints and journal bind to it, and it never changes.
- **Final name.** Frozen the first time response metadata reaches the service, or with the journal `intent` at the
  latest. Nothing changes it afterwards.
- **Migration 4** (forward-only) adds `jobs.staging_name` and `jobs.name_source`. Existing jobs become
  `staging_name = display_name` with `name_source = 'legacy'` (frozen), so their partial files, checkpoints and
  journal entries keep working unchanged.
- Job IDs, idempotency, checkpoint destination binding and journal recovery are unchanged.

### Allocation policy

- Partial files grow as bytes are written. Segmented transfers write at offsets and may leave sparse regions until
  they are filled.
- Nothing is pre-allocated, and **sparse sizing reserves no capacity**.
- The disk budget is an advisory snapshot (ADR 0009).

## Limitations and unverified cases

- Limits are per platform, not probed per volume: eCryptfs (143 bytes), some SMB/NFS shares and FAT 8.3-only volumes
  are refused at creation (`DESTINATION_UNWRITABLE`) rather than fitted.
- Windows long paths:
  - names are shortened to keep paths within 259 units only while the folder leaves 32 units;
  - deeper folders rely on the standard library's long-path handling, and other programs may not open such files.
- No RFC 2231 continuations (`filename*0*=`), no RFC 2047 encoded words, no MIME-type-based extension guessing.
- Case-insensitive comparison among jobs uses Unicode lower case. Windows' own upper-case table can differ for a few
  characters; the file system's own check still prevents overwriting.
- A file created at the frozen name after selection stops placement with an explicit error (never overwritten). The
  job is not renamed automatically.
- aria2 reports no response metadata: its jobs keep the URL-derived name.
- The `display_name` change (provisional → final) is not yet shown in the UI (B2).
- `DESTINATION_UNWRITABLE` from permission and read-only failures is classified, but no process test runs on a real
  read-only or ACL-restricted folder.
