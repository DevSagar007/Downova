# B0.4.2 — Rust HTTP backend prototype (`dm-backend-http`), first increment

- **Date:** 2026-10-25
- **Host:** Windows 11 Pro 10.0.26300 x64 (local developer machine). No other OS has run these checks yet.
- **Toolchain:** rustc 1.99.1, MSVC Build Tools 17.14
- **Decision:** [ADR 0004](../decisions/0004-rust-http-backend-prototype.md). aria2 stays the default backend.
- **Scope of this increment:** single-connection, whole-file HTTP/HTTPS. Validated resume and segmentation are
  refused explicitly (next increment).

## What was built

| Area | Implementation |
|---|---|
| Crate | `crates/backend-http` (`dm-backend-http`), depends on `dm-domain` and `dm-backend-api` only |
| Stack | reqwest 0.13.5 (`default-features = false`, `rustls-no-provider`, `stream`), rustls 0.23.46 (`ring`), rustls-platform-verifier 0.7.1, Tokio 1.54 |
| Trust | a rustls `ClientConfig` built by the backend: `ring` provider + platform verifier (OS trust store). Fixture CAs only through `HttpConfig.extra_roots` (`Verifier::new_with_extra_roots`). Verification is never disabled; the OS store is never modified |
| Transport | HTTP/1.1 only (ALPN `http/1.1`), no proxy, no cookie store, no referer, no decompression features, `retry::never()`, connect timeout 15 s, read timeout 30 s |
| Redirects | `Policy::none()`; followed manually, at most 10 hops; each hop's scheme gated by the capability report (`http`→`Http`, `https`→`Https`, anything else refused) |
| Scoping | credential headers (`is_sensitive_header`) and validators (`If-Match`, `If-None-Match`, `If-Range`, `If-Modified-Since`, `If-Unmodified-Since`) are sent only while the hop has the original origin; URL userinfo is converted to Basic auth by reqwest and not carried to other origins |
| Responses | final status must be `200`; `Accept-Encoding: identity` and any non-identity `Content-Encoding` refused; byte count checked against `Content-Length` (short → `NETWORK_OFFLINE`, long → `INVALID_RANGE`) |
| Errors | 401/407 `AUTH_REQUIRED`; 403/404/410 `LINK_REFRESH_REQUIRED`; 412 `REMOTE_CHANGED`; 416/206 `INVALID_RANGE`; 408/429/5xx `SERVER_BUSY` with `Retry-After` in `BackendError.retry_after`; TLS failures `TLS_HANDSHAKE_FAILED` with the reason (untrusted issuer, wrong host name, expired, …). Details never contain URLs; `reqwest::Error` is never formatted |
| Files | bytes stream through a 256 KiB buffer into `<name>.downova-part`, created with `create_new`; the destination must not exist. On success: flush, `sync_all`, then publish with a hard link (fails if the destination exists) or, where links are unavailable, a checked rename |
| Control | pause/remove/shutdown signal the task and wait for it (bounded 10 s, then abort): network and disk activity stop before the call returns, and the buffered bytes are flushed so the partial file equals the reported progress. `resume` with partial bytes → `BACKEND_CAPABILITY_UNAVAILABLE`; with zero bytes it restarts. `discard` deletes only the attempt's `.downova-part`, never a completed file |
| Refused | `max_connections > 1`, `Range`/`If-Range` request headers (`BACKEND_CAPABILITY_UNAVAILABLE`) |
| Service | `dm-service --backend aria2|http` (default `aria2`; `--aria2` only with `aria2`). The service binary installs the ring provider as the process default (see "Defect found") |
| Fixtures | the controlled fixture server and test PKI moved to `crates/test-fixtures` (`dm-test-fixtures`, dev-dependency only), shared by aria2 and the HTTP backend |

## Acceptance matrix (`crates/backend-http/tests/http_backend.rs`)

Runs in plain `cargo test` (no external binary). Oracle: SHA-256 of the published file.

| Case | Scenario | Outcome |
|---|---|---|
| H01 | known length, 200 | safe success; 1 request with `Accept-Encoding: identity`, no `Range`; no partial file left |
| H02 | unknown length (close-delimited) | safe success |
| H03 | zero bytes | safe success, empty file |
| H04 | known length, cut at 1 of 3 MiB | safe failure `NETWORK_OFFLINE`; exactly 1 request (no hidden retry); nothing published; partial kept until discarded |

| S01 | 401, 403, 404, 410, 412, 416, 500 | `AUTH_REQUIRED`, `LINK_REFRESH_REQUIRED` ×3, `REMOTE_CHANGED`, `INVALID_RANGE`, `SERVER_BUSY`; 1 request each; no secret in the error |
| S02 | 503 + `Retry-After: 30`, 429 + `Retry-After: 7` | `SERVER_BUSY` with `retry_after` 30 s / 7 s |
| D01 | 302 same origin with Authorization, Cookie, If-Match | safe success; scoped headers reach the same-origin target |
| D02 | 302 cross origin with the same headers | safe success; the origin got them, the redirect target got **none**; unscoped headers still sent |

| T01 | HTTPS, fixture CA as an explicit extra root | safe success |
| T02 | self-signed | `TLS_HANDSHAKE_FAILED` ("issued by an untrusted authority"); no HTTP request |
| T03 | trusted CA, wrong host name | `TLS_HANDSHAKE_FAILED` ("not valid for this host name"); no HTTP request |
| T04 | fixture CA not supplied (production trust) | `TLS_HANDSHAKE_FAILED`; proves the fixture CA is not trusted by default |
| X01 | remove during a transfer | partial file size identical at acknowledgement and 300 ms later; nothing published; attempt gone |
| X02 | pause, then resume with partial bytes | paused; partial file size equals reported progress; resume refused `BACKEND_CAPABILITY_UNAVAILABLE`; no new request |

Unit tests (7): status classification, Retry-After attachment, per-hop gate, origin scoping, no-overwrite publish,
file-name validation, capability report.

**Repeatability:** 10 consecutive runs of the matrix, 24/24 each.

### Defects found while building the matrix

1. **Fixture TLS flush (test infrastructure).** T01 hung in 2 of 5 runs at 2 031 616 of 2 097 152 bytes. The fixture
   server never flushed after writing a body; tokio-rustls keeps the last records buffered until a flush, so on a
   kept-alive TLS connection the tail could stay unsent. Fixed by flushing after every response. The aria2 matrix uses
   the same server and was re-run after the fix.
2. **TLS errors classified as network errors.** hyper-rustls nests `rustls::Error` inside two `io::Error`s, and
   `io::Error::source()` skips a custom payload. The classifier now descends into `io::Error::get_ref()`. T02–T04 now
   report `TLS_HANDSHAKE_FAILED` with the reason.
3. **Progress ahead of the disk.** On stop, the write buffer was dropped, so the partial file could be shorter than the
   reported progress (X01 first showed 0 B). The task now flushes before acknowledging a stop.
4. **Secret in `Debug`.** The backend's `Debug` printed the raw request URL. The attempt now formats a redacted source.
5. **Feature unification panic in `dm-service`.** Linking both backends unifies reqwest features: the TLS support enabled
   for `dm-backend-http` (without a bundled provider) also applied to the aria2 adapter's loopback RPC client, and
   `dm-service --backend aria2` panicked at startup ("No rustls crypto provider is configured"). Found by the CLI
   real-service test. The service binary now installs `ring` as the process default before anything else.

## Capability report

| Capability | Status | Evidence |
|---|---|---|
| `Http` | **supported** | H01–H06, S01–S02, D01–D05, X01–X05, Z01 |
| `Https` | **supported** | T01–T04 (fixture CA via explicit extra root; production trust rejects it) |
| `SegmentedHttp` | unsupported | not implemented; refused (X05) |
| `ResumeStrongValidator` | unsupported | next increment; partial resume refused (X02) |
| everything else | unsupported | HTTP/1.1 only, no proxy, no speed limits, HTTP(S) only |

Both started `unverified` and were promoted only after the matrix passed.

## Integration

- `crates/service/tests/http_backend_process.rs` (plain `cargo test`): the real `dm-service --backend http` process.
  - `hello` reports backend `http` with the report above.
  - A 3 MiB download with a trusted SHA-256 completes and matches; the token is redacted.
  - 503 + `Retry-After: 1` once → the service waited ≥ 1 s (1.88 s observed), retried from zero (no `Range`), completed.
  - A body cut once → fresh attempt, completed, SHA-256 match.
  - HTTPS to an untrusted certificate (production trust) → failed `TLS_HANDSHAKE_FAILED`, no HTTP request.
  - Cancel during a slow transfer → `cancelled`; partial size unchanged after the acknowledgement; nothing published.
  - `--backend curl` and `--backend http --aria2 x` exit 2.
- `crates/cli/tests/real_service.rs::cli_against_real_service_with_http_backend` (`#[ignore]`, run by `pnpm verify`):
  `dm --json add http://…?token=…` → `completed`; 2 MiB file SHA-256 `4d8a372d…7441b` equals the payload.

## Limitations

- Windows only so far; macOS (Security.framework) and Linux (webpki + system roots) verifier paths need CI.
- Public HTTPS sites are not exercised by tests (no external network); production trust is the platform verifier.
- No resume of partial data and no segmentation; interrupted transfers restart from zero via the service.
- Unknown-length truncation (H05) is undetectable without a trusted size or hash.
- Revocation checking is whatever the platform verifier does on each OS; not tested here.
- New dependency tree (reqwest, hyper, rustls, rustls-platform-verifier, ring) needs the licence and advisory review
  (REL-03, REL-05) before shipping.
