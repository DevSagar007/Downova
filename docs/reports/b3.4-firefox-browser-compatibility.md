## 2. What now works

**Firefox (BRW-08):**
- In Firefox 140 or later, right-click an http(s) link and choose **Download with Downova**.
- The extension sends the link to Downova on this computer through native messaging. The popup shows that Downova
  **accepted** it, not that it started or finished, and the file is downloaded by Downova.
- Acknowledgement, the same-key retry after a lost answer, the popup's service check, the missing-host and
  service-down answers, and the English and Bangla text work as in Chrome and Edge.
- Every download Firefox starts itself (a normal link, `blob:`, form posts) stays in Firefox.
- **Not offered in Firefox:** automatic capture, downloads with your sign-in, reconnect, containers, private
  windows. Their menus and permissions are absent, their requests are refused, and the popup says what is
  Chrome/Edge only.
- **Distribution:** the Firefox build is **unsigned**. Load it as a temporary add-on
  (`about:debugging` → Load Temporary Add-on), from `extension-firefox-unpacked/` or `downova-firefox-unsigned.xpi`
  in the package. Signed distribution needs an add-on ID the maintainer owns.

**Registration (BRW-07):**
- `dm-browser-host register|repair|unregister|status --browser firefox` (and `--browser all`).
- Firefox gets its own manifest (`allowed_extensions`) in Mozilla's per-user location: Windows uses its own folder
  and the `HKCU\Software\Mozilla` key. It never overwrites a Chrome or Edge entry, and the ownership rules are
  unchanged.
- The NSIS installer, its uninstaller and the app's first launch include Firefox.

**Browser packages (BRW-09):**
- **Help → Browser connections…** lists every browser found on this computer with:
  - how it is installed (normally, Snap, Flatpak or unknown);
  - whether its connection points at this Downova;
  - the support verdict with its reason;
  - **Repair**.
- The same information is in `dm-browser-host status --json`. It is categories and codes only, never a path.
- A Snap or Flatpak browser is never called supported: Snap Firefox is "not tested" (portal path untested), and
  other Snap browsers and every Flatpak are "not supported".

## 3. What changed

- **Host:**
  - `caller()`: Firefox's `<manifest path> <add-on id>`, with the ID checked against an exact list and the path a
    shape check only; Chrome origins unchanged; anything else refused with one framed reply;
  - `Browser::Firefox`, `callers_for`, `--browser all`;
  - `detect` (bounded package detection plus the verdict matrix); status JSON with packages and verdicts.
- **Extension:**

    reconnect page Chromium-only);
  - `features.ts` (`FEATURES`), background gating, the menu recreated at browser start;
  - `isHostMissing` (Firefox's "No such native application …");
  - Firefox notices in the popup and options page (English and Bangla);
  - e2e-only hooks (`features`, `target`, `menuExists`, self-opened page for Firefox automation).
- **Desktop:**
  - `browser_setup::connections` and `repair` (path-free; `--replace` never used);
  - Tauri commands `browser_connections` and `browser_repair` with permissions;
  - client, provider and fake;
  - `BrowserConnectionsDialog` (one repair per browser, stale answers dropped);
  - English and Bangla strings for every new message;
  - first launch registers Firefox.
- **Packaging and tooling:**
  - `scripts/package.mjs` builds the Firefox target, checks its manifest and contents, and writes
    `EXTENSION-FIREFOX-SHA256SUMS.txt` and an unsigned `.xpi`;
  - `pnpm verify` builds both targets;
  - `scripts/e2e/firefox-handoff.mjs` (real Firefox) and `scripts/acceptance/browser-lifecycle-acceptance.mjs`
    (packaged lifecycle);
  - the NSIS hooks;
  - `.gitignore`, eslint and structure ignore `dist-firefox/`.

## 4. Defects found and fixed

- **Firefox's missing-host error was reported as "uncertain"** (found by the real-Firefox F8). The extension only
  recognised Chrome's wording. A missing host means nothing was sent, so it is now "unavailable / host_missing",
  with a unit test using each browser's exact wording.
- **Two problems in the first Firefox harness approach,** both test-tooling, not product:
  - BiDi may not navigate a tab to an extension URL, so the e2e build opens its own page;
  - evaluating in an extension page needs Firefox's documented automation switch for the test process.
- **Lint failures:**
  - the new dialog called `setState` synchronously in an effect; restructured;
  - eslint linted the built `dist-firefox/`; it is now ignored like `dist/`.
