## What changed

### Shell bridge (`apps/desktop/src-tauri`)

- **Commands** (`src/downloads.rs`, wired in `src/lib.rs`):

  | Command | Contract method |
  |---|---|
  | `downloads_list` | `downloads.v1.list` |
  | `downloads_add(url, idempotency_key)` | `downloads.v1.add`, destination profile `downloads` |
  | `downloads_pause` / `downloads_resume` / `downloads_cancel(job_id)` | `downloads.v1.pause` / `resume` / `cancel` |

  The method names are constants. There is no generic forwarding, and no filesystem, SQLite or engine access.
- **Validation in Rust before sending.** `dm_domain::validate` (new; the browser host now uses the same functions):
  - http(s) only;
  - no credentials, spaces or control characters;
  - at most 8 KiB;
  - a key of 8–128 `[A-Za-z0-9_-]` characters;
  - a `job_…` ID.
- **Timeouts:** connect 3 s, list 5 s, acknowledgement 15 s.
- **Errors keep `ErrorData`** and add an outcome:
  - `unavailable`: nothing was sent;
  - `uncertain`: a mutation was sent, with no acknowledgement;
  - `rejected`: the service or the argument check refused it.
- **SEC-05:**
  - `build.rs` declares exactly the six app commands in the Tauri app manifest;
  - `capabilities/default.json` grants each by name (`allow-service-connect`, `allow-downloads-*`);
  - generated permission files are ignored like `gen/schemas`.
- **Smoke-only** (`--features smoke`, `src/smoke.rs`): the existing handshake report, plus a driver that fills the real
  Add URL dialog and records `downloads_list` until the job ends. It is not compiled into release packages.

### UI (`apps/desktop/src`)

- **`ServiceClient`** gains `listDownloads`, `addDownload`, `pauseDownload`, `resumeDownload` and `cancelDownload`.
  `ServiceCallError` carries `{ outcome, error }`. The plain-browser client refuses every call as unavailable.
- **`ServiceProvider`** owns the connection and the list:
  - **Polling:** about once a second, never overlapping, and run immediately after every mutation.
  - **Stale answers dropped:** answers from an older connection, and lists that started before the latest acknowledged
    mutation (so a slow poll cannot undo a Stop).
  - **When the service becomes unreachable:** it stops polling and keeps the last rows marked stale. Reconnect finds or
    starts the service.
  - **Mutations** merge the acknowledged snapshot and are never repeated automatically.
- **Add URL dialog** (`features/downloads/AddUrlDialog.tsx`):
  - the URL field is focused on open (new `data-autofocus` support in `Dialog`);
  - inline validation that mirrors the Rust check, with `aria-invalid` and an `alert`;
  - one request at a time: synchronous guard, "Adding…", the button unavailable while pending;
  - the idempotency key belongs to the link text, so a retry after an uncertain answer reuses it and the service
    returns the same job;
  - refusals are explained with the CORE-11 catalogue.
- **Selection** by job ID:
  - the file-name cell is a button with `aria-pressed`;
  - a click or ↑/↓ selects;
  - the selection survives a file-name change;
  - the selected style uses the existing `--color-row-selected` tokens.
- **Toolbar and menus:**
  - Add URL, Resume and Stop are wired, in both the toolbar and the File/Tasks menus;
  - the reasons come from the snapshot: no selection, already paused, not paused (a waiting job continues by itself),
    finished, cancelled, failed — a failed job is never resumable;
  - Delete and "Remove from list" stay unavailable with an explicit reason and are never mapped to cancel;
  - the other commands keep "connected in a later milestone"; cancel exists only at the client/bridge boundary.
- **Presentation:**
  - a transfer without a total shows its received size;
  - completed rows show their verification ("Verified: SHA-256 recorded" / "matches the expected SHA-256");
  - below the list, a Banner shows the selected job's error summary, action and follow-up, or why the last Stop/Resume
    failed;
  - above the list, a Banner shows a lost or incompatible service, with Reconnect where it applies;
  - speed, ETA and last try stay "—".
- **Copy:**
  - new English and Bangla strings for the dialog, command reasons, service notices and verification;
  - About and the build label no longer say that nothing can be downloaded;
  - the plain-browser reason says it is a browser preview without the service.

**What each layer proves:**
- **UI tests** prove the window's behaviour against the `ServiceClient` interface (states, keyboard, copy, idempotency
  handling, stale answers). They never touch Tauri or the service.
- **Bridge tests** prove the shell commands against a fake service on the real IPC transport.
- **Packaged step F** proves the production path — dialog → Tauri IPC → Rust command → real service → file — on
  Windows. It does not exercise selection, Stop or Resume in the packaged app.

## Limitations

- **OS coverage:** Windows only until CI and package smoke run on this tree. Step F has not run on macOS or Linux.
- **Updates by polling (about 1 s):** no event stream (ARCH-08 stays `documented`). Up to a second of latency, and one
  IPC connection per call.
- **Selection:** single selection only; no range selection, context menu, details dialog or progress bar.
- **Status cells:** distinguished by text, not yet by a tone icon (UI-03 stays `in-progress`).
- **Cancel** has no UI control. Delete and "Remove from list" wait for removal semantics (CORE-10).
- **Add** uses the `downloads` profile only; there is no destination choice or expected checksum in the dialog.
- **Uncertain adds:** the window keeps the unconfirmed link and its key, so reopening Add URL offers the same link
  and a retry reuses the key. Restarting the desktop app forgets them; the list then shows whether the first request
  arrived.
- **Selected-row style:** after the packaged run, the selected-row rule was made as specific as the hover rule, so a
  hovered selected row still looks selected. The packaged screenshot predates this CSS-only change.
- **Bangla:** the copy has had no native-speaker QA pass yet.

- **Start:** a second launch focuses the existing window.
- **Acceptance:**
  - Testing Library coverage for the exit confirmation;
  - packaged smoke steps for close-to-tray (service and transfer continue) and for "Exit and stop downloads" (the
