## Search

`apps/desktop/src/features/downloads/search.ts`:

- `normalizeSearchText` trims, applies NFKC and lower-cases, so Bangla, right-to-left and width variants match;
- `sourceHostname` parses the stored source and returns only the lower-cased hostname (a trailing dot is removed); a
  malformed source yields no hostname;
- `matchesSearch` accepts a row when its display name or its source hostname contains every query term. The full URL,
  query, fragment and credentials are never used for matching, displayed in the field or announced.

`DownloadSearch.tsx` / `.css`:

- a labelled `type="search"` field above the table with an accessible name (`search.label`), a decorative icon and an
  explicit Clear button; the field is limited by `--search-max-width` and uses logical properties;
- the query is local presentation state. It combines with the category filter and the table's stable sort;
- results are derived from the same snapshot the table renders, so a poll cannot make the count disagree with the
  rows;
- match counts are keyed by the normalised query and announced through a polite live region, throttled so typing does
  not flood assistive technology; blank queries and empty history stay quiet;
- Ctrl/Cmd+F focuses the field and does not steal focus while a dialog is open; Escape clears the field while it is
  focused;
- selection stays by job ID. A selected row that the query hides keeps its ID, is drawn as not pressed and exposes no
  row command; clearing the query restores it.

The table now distinguishes `loading`, `noMatches` (search or category produced nothing) and the genuine empty or
disconnected states, rather than presenting "no downloads" for a filtered view.

## Clear finished

`clear.ts`:

- `isFinished` covers completed, failed and cancelled snapshots; paused, blocked, waiting and finishing jobs are never
  targets;
- the dialog freezes target IDs when it opens, so a job finishing while the dialog is open is not swept in silently;
- at most three `downloads.v1.remove` calls are in flight; each row disappears only after its own acknowledgement;
- duplicate confirmation is ignored by a busy ref, so a second click cannot start a second sweep;
- a partial failure keeps the failed rows and reports the name, error kind and offered action per row; a successful
  sweep closes the dialog and announces the count.

`ClearFinishedDialog.tsx` uses the existing `Dialog`, `Button`, `Banner` and translation components. The File menu
entry is disabled with `clear.none` when no row is finished, `offline` while unavailable and `busy` while another
mutation runs. Files are never deleted; `remove` only tombstones the job row, and the running/paused jobs are never
sent.

### Service defect found by the packaged smoke

The first packaged runs failed J2: a failed job kept `attempt: Some`, so `Core::remove` refused it even though the
job was terminal. The service now rejects only a non-terminal job or one with `finalizing.is_some()`. For a
terminal failed attempt it calls `backend.remove(&handle)` (which stops engine bookkeeping and keeps the partial and
output files), clears the attempt and then persists the tombstone. The regression test extends
`only_finished_jobs_are_removed_and_files_are_never_touched`: a queued job is admitted after cancellation, forced to
`RemoteChanged` failure with an owned attempt, then removed successfully with `attempt_id: None`.

## Limitations

- A retention policy is not implemented, so CORE-10 stays `in-progress`; there is no automatic expiry, undo, or
  "delete file" action.
- Search is local to the loaded snapshot; there is no server-side history query and no pagination.
- The count announcement is throttled and follows polling (about 1 s), like the other live regions.
- Linux and macOS were not run for B2.7; CI and package-smoke need a pushed commit, which was not requested.
- Human acceptance H1–H11 (right-click, tray, screen reader, 200 % zoom) remains not run.
- The service fix was proven by the Windows core and packaged smoke tests only.
