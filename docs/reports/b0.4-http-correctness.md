- **Date:** 2026-10-21
- **Host:** Windows 11 Pro 10.0.26300 x64 (local developer machine). No other OS has run these checks yet.
- **Toolchain:** rustc 1.99.1, MSVC Build Tools 17.14
- **aria2:** 1.37.0, `aria2-1.37.0-win-64bit-build1.zip` (SHA-256 `67d01530…d9b288`, pinned by `scripts/fetch-aria2.mjs`)
- **Commands:**
  - `cargo test -p dm-backend-aria2 --locked --test http_correctness -- --ignored --nocapture --test-threads=2` (27 tests)
  - `cargo test -p dm-service --locked --test process -- --ignored --nocapture` (6 tests)
  - `cargo test -p dm-cli --locked --test real_service -- --ignored --nocapture` (1 test)
  - all three also run in `pnpm verify` (group `aria2`); `pnpm verify:strict` 15/15 PASSED (Windows 11, 2026-10-21)
- **Decision:** [ADR 0003](../decisions/0003-aria2-go-no-go.md)

## Method

- **Fixture server** (`crates/backend-aria2/tests/support/`): loopback HTTP/HTTPS with scriptable routes (range
  handling, ETag, Content-Length on/off, truncation, Content-Encoding, Content-Disposition, redirects, scripted status
  sequences with Retry-After, slow bodies, body swaps during a transfer). Every request is logged with its headers, so
  tests check `Range`, `If-Range`, `Authorization` and `Cookie` as sent.
- **Oracle:** the SHA-256 of the file against the expected payload. When old and new versions have the same length, a
  prefix/suffix comparison names the mixture (`MIXED: starts with A, ends with B`).
- **Classification:**
  - **safe success:** engine reports complete and the bytes are exactly the expected payload;
  - **safe failure:** engine reports failure with a classified `ErrorKind`; no false completion;
  - **unsafe:** engine reports complete with wrong or mixed bytes, or leaks a credential;
  - **not tested:** the scenario could not be exercised honestly on this host.
- **Two configurations:**
  - **engine** (`max_tries = 5`, the B0.1 default): raw aria2 behaviour including internal retries;
  - **production** (adapter defaults after B0.4: `max_tries = 1`, `--continue=false`, credential headers refused,
    one connection): what `dm-service` runs.
- Unsafe engine outcomes are **asserted as unsafe**: if aria2 behaviour changes, the test fails and the decision must be
  revisited. No check was weakened and certificate verification was never disabled.

## Review fixes (same day)

A review of the B0.4 implementation found and fixed:

1. **Stale resume gate (service).** `resume` checked the byte count from the last 400 ms poll. A pause between two polls let a
   partial transfer through to aria2's validator-less resume (the C06 path). The gate now reads the engine's current
   progress first. Regression: `resume_gate_uses_fresh_engine_progress_not_the_last_poll` (failed before the fix).
2. **Status parsing.** `http_status` took the first `status=` in aria2's message, which begins with the request URL, so
   `?status=200` in a URL changed the classification. It now takes the last one. Regression:
   `a_status_parameter_in_the_url_does_not_change_the_classification`.
3. **New evidence:** D04 and D05 (above).

## Fixes made in B0.4

All in the adapter or classification; no engine change.

1. `max_tries` 5 → 1: removes aria2's unvalidated internal resume (C01–C04 → C08 safe).
2. `--continue=true` → `--continue=false`: no append to foreign files (K03).
3. Credential headers refused unless an explicit unsafe test flag is set (D02 → D03).
4. `classify(code, message)`: distinguishes 401/403/410/429/5xx behind aria2 code 22, 503 (code 29), TLS handshake
   failure, and interrupted transfers ("No URI available.", code 1). Only status digits and fixed markers are read;
   the message itself (it contains the raw URL and token) is never forwarded.
5. New `ErrorKind`s `SERVER_BUSY` (retryable, wait) and `TLS_HANDSHAKE_FAILED` in the contract.
6. `capabilities::report(max_tries)`: `Http` supported only with `max_tries = 1`.

## TLS backend and bundled libraries

`aria2c --version` of the pinned build:

```text
Enabled Features: Async DNS, BitTorrent, Firefox3 Cookie, GZip, HTTPS, Message Digest, Metalink, XML-RPC, SFTP
Libraries: zlib/1.3 expat/2.5.0 sqlite3/3.43.1 GMP/6.3.0 c-ares/1.19.1 libssh2/1.11.0
Compiler: mingw-w64 8.0.0 (alpha) / gcc 10-win32 20220113
```

- **TLS backend: WinTLS (SChannel), not OpenSSL.** No TLS library is listed; the binary imports `Secur32.dll` and
  `CRYPT32.dll` and contains no OpenSSL version strings. Upstream's `mingw-config` for release-1.37.0 configures
  `--without-openssl --without-gnutls`. The archive's `LICENSE.OpenSSL` file is a leftover; the B0.1 report's claim
  is corrected.
- Consequences: trust comes from the Windows certificate store and TLS fixes come from Windows Update; `--ca-certificate`
  is not honoured (T01).
- **Dated libraries** (checked against upstream advisories, 2026-10-21):
  - **libssh2 1.11.0:** 1.11.1 contains the Terrapin (CVE-2023-48795) mitigation. Affects SFTP only; SFTP is not a
    supported capability.
  - **expat 2.5.0:** predates fixes for CVE-2023-52425, CVE-2024-28757 and CVE-2024-45490 (fixed by 2.6.3). Used for
    Metalink/XML-RPC parsing; the adapter uses JSON-RPC and no Metalink.
  - **c-ares 1.19.1:** predates 1.27.0 (CVE-2024-25629, reading `/etc/resolv.conf`-style config). Applicability to the
    Windows build is limited but not proven absent.
  - Verdict: acceptable for local test fixtures; **not acceptable to ship**. REL-05 requires a rebuilt sidecar.

## Limitations

- Windows only. T01 success on an OpenSSL/GnuTLS build, and every other case on macOS/Linux, need a CI run.
- K02 did not exercise a non-zero-offset crash resume.
- Retry-After/backoff is not implemented in the service yet (B1); S01/S02 show only classification.
- Bangla filenames are covered only as an unsafe server suggestion that is ignored (N01); normalisation is E04 (B1).
