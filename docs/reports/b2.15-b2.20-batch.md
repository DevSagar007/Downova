## 1. Functionality completed

### B2.15 Capture synchronization

**What failed.** Windows Edge C1 in smoke #32 reported `state=accepted, browser_side=running` together with
`browser_state=interrupted/USER_CANCELED`, one native job and the right SHA-256. The capture worked; the test
asserted on a stale snapshot:
1. `captureFor()` returns as soon as the record leaves `evaluating`/`sending`.
2. `deliver()` stores `accepted` *before* `takeOver()` finishes.
3. C1 then waited for the browser and the job, but asserted on that first object.

**Test fix.** C1 now waits, within its deadline, for the persisted takeover outcome (`accepted` with the browser
side no longer `running`) and re-reads the record. Its independent assertions stay:
- matching acceptance;
- browser interruption attributed to Downova;
- one job;
- SHA-256.

It also records `first_settled` and `cancel_requested`.

**Product races examined after the test fix:**
- **Two takeovers of one record.** Resume and a late acceptance could both run a takeover of the same record in
  one worker. There is now one takeover per record per worker, so the browser copy is cancelled once.
- **Other interruptions.** An interruption during the takeover that is not `USER_CANCELED` (for example a network
  failure) is now `kept` and is no longer claimed as Downova's cancel.

**New deterministic tests.** Nine interleaving tests delay storage writes, native replies and the cancel callback,
and fire browser events before and after the cancel promise. They cover:
- a worker stopped after the cancel intent was stored;
- a genuine user cancel;
- the browser completing during the takeover;
- capture disabled or permission revoked while the reply is pending;
- two concurrent takeovers.

Fallback and browser-safety behaviour are unchanged.

### B2.16 Retry (CORE-03)

**`downloads.v1.retry`** applies to a listed, failed job that is not finalizing.
- **Refused:**
  - completed, cancelled and removed jobs;
  - expired links, pointed to Refresh link;
  - sign-in failures.
- **Starts from zero.** A failed job has no resume point, so partial data is discarded only with
  `discard_partial: true`; otherwise the request is refused with `choose_restart_or_keep`.
- **Same job.** Queue, priority, destination, names and the trusted checksum are kept. The job goes through normal
  admission, so global, queue and stopped-queue limits apply.
- **Safe to repeat.** A durable `operation_id` (migration 8) is committed with the reopen:
  - double clicks, lost acknowledgements and restarts produce one attempt;
  - the same ID with a different request is `IDEMPOTENCY_CONFLICT`;
  - `expected_attempt_id` refuses a job that changed meanwhile;
  - the old attempt's partial output is released before the commit, and its late callbacks are dropped.
- **Retention:** the reopen clears `finished_at_ms`, and nothing else does (ADR 0018 amended). A retried job that
  completes is never expired by its old failure's timestamp.
- **Desktop:**
  - File → Retry… (previously an unwired "Redownload") and a primary "Retry…" button in the details;
  - a confirmation dialog that states the bytes discarded;
  - an uncertain answer is repeated with the same operation ID.
- **CLI:** `dm retry`.

### B2.17 Refresh link (COR-06)

**`downloads.v1.replace_source`** applies to a paused or failed job.
- **Keep progress** only when all of these hold:
  1. The HTTP backend's `verify_replacement` resolves the new link through the gated redirect path.
  2. It gets a `206` for the last confirmed bytes (at most 64 KiB) with the same strong ETag, total length and
     exact `Content-Range`.
  3. Those bytes equal the bytes on disk.
  4. The resource is the same (origin and path) **or** the job has a trusted SHA-256.

  The job then continues under a new attempt restored from the rebound checkpoint. Its source, checkpoint and
  operation are committed in one transaction.
- **Otherwise** the answer is `choice_required` with a reason, and nothing changes.
  - **Restart from zero** is a separate, explicit request.
  - **Keep current download** sends nothing.
- **Ordering:** the old source, partial data and checkpoint stay until the commit. A kill before the commit
  recovers the old source.
- **Privacy:** the link never reaches logs, events, snapshots or errors (snapshots show `redact_url`).
- **Desktop:** File → Refresh link… and a details button. The dialog has a labelled, validated field, a localized
  reason, and the two choices.
- **CLI:** `dm refresh-link [--restart]`.

### B2.18 Checksum input and presentation (COR-05)

**Existing behaviour, kept:** a trusted SHA-256 must already match before placement, and a mismatch gives
`CHECKSUM_MISMATCH`.
**Added:**
- **Input:** Add URL has an optional "Publisher's SHA-256" field (exactly 64 hex digits, explained inline), and
  `dm add --sha256` does the same.
  - It is sent only when given, so earlier requests keep their idempotency fingerprint.
  - Snapshots carry `checksum_expected` (never the value).
- **Details panel:**
  - "Publisher checksum matched" and "SHA-256 computed locally (no publisher checksum)" are shown separately, with
    the hash.
  - The old list wording "Verified: SHA-256 recorded" overstated a local hash and is corrected.
  - A mismatch explains what to check, with Retry and Refresh link as the recovery, in English and Bangla.

### B2.19 Folder controls (CORE-07, ADV12, SEC-03)

**Browse…** sits beside each rule folder (native dialog, `tauri-plugin-dialog` 2.8.4).
- It only fills the field: cancel changes nothing, and Save still goes through `settings.v1.set`.

**Open containing folder** (File menu and details, keyboard-reachable).
- The shell asks the service for the job's bound folder (`downloads.v1.locate`); a renderer path is never trusted.
- It selects an existing file with `reveal_item_in_dir` (`tauri-plugin-opener` 2.7.2). Otherwise it opens only a
  directory, checked without following links right before the call.
- A missing file, folder or drive is explained.

**Isolation and the SEC-03 guard.**
- Both plugins are used from Rust only, in one adapter (`folders.rs`); the webview gets no plugin permission.
- The SEC-03 guard is narrowed, not removed:
  - exactly one opener dependency;
  - only the adapter uses it;
  - only the `downloads_reveal` command reaches it;
  - exactly one `open_path`, after its directory check, with no "open with" program;
  - no `open_url`.

### B2.20 Extension English/Bangla

Everything below now follows the browser language, from the one existing catalogue:
- the explicit hand-off popup: states, service readiness, outcomes, Retry/Dismiss/Clear and their accessible names,
  empty and loading text, static text and the page language;
- the context-menu title.

**Stored state:**
- Hand-off records store stable `code`s, and readiness answers carry a `code` with interpolation values.
- Translated prose is never stored.
- Records from before B2.20 render from their state and keep their idempotency keys.
- Changing language only re-renders.

**Wording:** the accepted text now says acceptance does not mean the transfer started or finished. Redaction is
unchanged.

## 4. Supported Retry and link-replacement cases

| Case | Result | Evidence |
|---|---|---|
| Failed job, no partial data | Retry: same job, new attempt, from zero | core, process, smoke M2 |
| Failed job with partial data | Refused until `discard_partial`; then from zero | core, UI |
| Repeat, double click, lost acknowledgement or restart (same operation) | One attempt | core, process (kill), UI |
| Completed, cancelled, removed or finalizing job | Refused | core, smoke M2 |
| Expired link (403/404/410) or sign-in | Retry refused with Refresh link / sign-in advice | core, process, smoke M3 |
| Paused job, new signature of the same resource, same ETag, length and confirmed bytes | Progress kept, completes byte-exact | backend S01, process (kill), smoke M3 |
| Another path, or an origin-changing redirect, with the same ETag and bytes | Kept only with a trusted SHA-256; otherwise choice | backend S04, core |
| Same-length changed content (new or the same ETag) | Choice; nothing spliced | backend S02, process |
| Missing or weak ETag, changed length, Range ignored | Choice | backend S03 |
| Failed job (no resume point) and Keep progress | Choice (`no_checkpoint`); Restart works | core, process, smoke M3 |
| Restart chosen | This job's partial data only, from zero, new link | core, process |
| aria2 backend | Retry after a restart refused (typed); Refresh link can only restart | default trait methods |
