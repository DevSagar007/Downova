# B2.32 installed-app acceptance runbook

- **Purpose:** the installed-app and human checks that B2 still needs, as one executable procedure. Automated
  checks (packaged smoke, the concurrency acceptance script) never stand in for these rows.
- **Who:** a tester with a **clean VM or a separate OS account** on each target OS (Windows 11 x64, macOS arm64,
  Ubuntu 22.04/24.04 x64). Never the developer's everyday account: installing registers the browser helper and
  shortcuts for that user, and the app takes a per-user single-instance lock.
- **Build:** the normal (not smoke) package, recorded by SHA-256 in PROGRESS.md and the B2.32 report. Verify the
  hash before installing: `Get-FileHash <file> -Algorithm SHA256` on Windows, `shasum -a 256 <file>` on macOS and
  Linux.
- **Recording:** each row gets PASSED, FAILED or NOT RUN, the build hash, the OS and browser version, who observed it
  (human or agent), and evidence (a screenshot, the fixture log, a hash). Page zoom (Ctrl/⌘ +, which the smoke
  probe also uses) and **OS display scaling** (Windows Settings → Display → Scale; macOS Displays; GNOME Settings →
  Displays → Scale) are different checks: record which one was used.

## 0. Setup (each OS)

1. **Fixture**, on the test machine or the LAN: `node scripts/acceptance/fixture-server.mjs --port 8765`. It prints
   every SHA-256 and serves the scenarios. Open `http://127.0.0.1:8765/` in Chrome and Edge.
2. **Large files for the concurrency rows:** `node scripts/perf/fixture-process.mjs --count 6 --size-mib 256`. Its
   first line is JSON with `base` and each file's SHA-256. Add `?slow=100` to the URLs to pace them at about
   0.6 MB/s per request.
3. **Install:**
   - Windows: `Downova_0.1.0_x64-setup.exe` (per-user).
   - macOS: open the `.dmg`, move Downova to Applications, open it once.
   - Linux: `sudo dpkg -i downova_0.1.0_amd64.deb`, or run the AppImage.
4. **Extension:** load `extension-unpacked/` from the package folder (Chrome/Edge → Extensions → Developer mode →
   Load unpacked).

## 1. Installed concurrency (new in B2.32)

| ID | Steps | Expected |
|---|---|---|
| C1 | Options → Simultaneous downloads | "What this allows" shows the saved limit 3, Main 3, "Main can run at once 3" |
| C2 | Set the limit to 6 and save; press Change queue limit; set Main to 6 → Set limit → Done | Back in Options: Main 6, "Main can run at once 6"; `dm concurrency` says 6, `dm queues` shows main 6 |
| C3 | Add the six large URLs (Add URL, or `dm add`) | All six rows show a rising percentage before any completes; `dm list` bytes rise for all six |
| C4 | While they run, set the limit to 2 and save | No running download stops; "Active now" stays 6 with the "more downloads are active than the limit" note; a seventh URL added now waits |
| C5 | Set the limit back to 6 | The waiting download starts within a few seconds |
| C6 | Pause one; stop Main in Manage queues, then start it; cancel one | The paused one gains no bytes; stopping Main holds its downloads; starting it resumes them within the limits; the cancelled one ends cancelled, with no final file |
| C7 | Quit with tray → Exit and stop downloads; open Downova again | Limits still 6 and 6; downloads continue (paused ones stay paused); every completed file matches its SHA-256 |

## 2. Existing human checks (procedures unchanged)

- **H1–H9:** B2.24–B2.27 report §7. Covers right-click capture, the popup in Bangla, tray Open and Exit, Browse…,
  Open containing folder, Retry and Refresh link, logout/sleep/reboot, and screen readers.
- **N1–N4 (notifications):** visible, hidden and closed window; blocked by the OS; Bangla; selecting a notification.
- **A1–A3:** screen readers on the 10,000-record list; removing the focused row; 200 % **OS scaling** and page zoom,
  long Bangla names.
- **B2.32 addition to A3:** with a download selected (its details panel open) at 200 % OS scaling and at 200 % page
  zoom, at least one list row stays visible, and the details panel scrolls instead of covering the list.

## 3. Fallbacks and uninstall

| ID | Steps | Expected |
|---|---|---|
| F1 | Stop the service (tray → Exit and stop downloads), then right-click a fixture link → Download with Downova | The browser keeps the download (fallback) and the popup states why; never two downloads |
| F2 | Run `dm-browser-host status`, then `dm-browser-host unregister` (from the install folder), then right-click a link | `status` lists the registered browsers; after `unregister` the browser keeps the download and the popup states why; `dm-browser-host repair` restores it |
| F3 | Lost acknowledgement / timeout | **No installed-app scenario exists** (the fixture has none). Covered only by unit tests (`apps/extension/src/handoff.test.ts`, "a timeout is uncertain…"); this row stays NOT COVERED |
| U1 | Uninstall (Windows Settings → Apps; macOS: run `dm-browser-host unregister`, then move the app to the Trash; Linux: `sudo apt remove downova`) | Downloaded files and the download folder stay; only Downova's own registry keys (Windows: `HKCUSoftware<vendor>NativeMessagingHostscom.downova.host`, manifest under `%LOCALAPPDATA%Downova
ative-messaging`) and manifests go; an unrelated manifest in the same folder stays |
