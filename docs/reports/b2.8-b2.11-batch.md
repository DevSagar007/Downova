## Completed functionality

### B2.8 — duplicates, destinations, names (CORE-07, SEC-03)

- **Duplicate check:**
  - `downloads.v1.check` lists same-link jobs (exact URL; only scheme and host case-folded; never the redacted URL),
    never returning the URL.
  - `add` takes an optional `on_duplicate` (`allow` default, `refuse`), decided under the coordinator lock after
    the idempotency replay.
  - Concurrent refusing adds create exactly one job, and the same key still returns the original job.
  - Optional fields join the fingerprint only when present, so retained keys keep their fingerprints.
- **Desktop Add URL:**
  - it checks first and offers Show existing download / Download again / Cancel;
  - it adds with `refuse` and re-checks when another client was faster;
  - Download again is a new request (new key, `allow`);
  - an uncertain add is repeated with the same key and options.
  - It also offers category and queue choices.
- **Destination rules:**
  - Options → Downloads holds one folder per category, validated by the service (absolute, existing, no `.`/`..`).
  - The folder is fixed per job at acceptance; editing a rule never moves a partial file, checkpoint or journal
    entry.
  - Browser hand-offs never set a folder, queue or duplicate policy.
- **Collisions:**
  - `rename` (the default) or `ask`;
  - `ask` holds the verified file with `name_conflict` until "Save as <name>" (`downloads.v1.confirm_name`) or
    cancel;
  - a name taken between selection and placement is replaced by the next free one, journaled first (amends ADR 0011);
  - nothing is ever overwritten.
- **CLI:** `dm add --refuse-duplicate --category --queue`.
- **SEC-03:** a structural guard test (process starts allowlisted, no opener dependency or capability, no OS open
  entry points).

### B2.9 — event stream (ARCH-08)

- **Service:** `events.v1.subscribe` returns a snapshot with its sequence watermark. Events follow on the same
  connection, as whole lines:
  - diff-coalesced `progress` every 400 ms;
  - `job_added`, `job_changed` and `job_removed` at once;
  - the next sequence for every event, as a decimal string.
- **Subscribers:** bounded (1024 events), `try_send` only. Overflow ends with `snapshot_required`.
- **Shell:** `events_subscribe` / `events_unsubscribe` forward events tagged with a subscription number.
- **Client:** buffers early events and ignores foreign subscriptions. The provider:
  - applies an event only on the same instance and the next sequence;
  - resubscribes on a gap, a new instance, `snapshot_required` or the end of the stream;
  - never brings a removed job back.
- **Fallback:** polling remains only as the explicit, tested fallback for a service that refuses subscriptions.
- **Preserved:** B2.7 search, selection, Clear finished and mutation acknowledgements are unchanged; their tests
  run on the fallback path and the stream path.

### B2.10 — lifecycle (ARCH-09)

- **Native-host disconnect:** a disconnect before or after the acknowledgement, followed by a same-key retry,
  leaves one job.
- **Service restart with the UI open:**
  - attach-only probes (0.5, 1, 2, 4, 8, 8 s), never `connect`;
  - a fresh subscription on the new instance;
  - no replay of uncertain mutations;
  - then a Reconnect button.
- **Exit and stop downloads:** ends the stream and disables reconnection first. A failed or uncertain exit
  re-attaches only.
- **Service:**
  - a bounded shutdown checkpoint (10 s);
  - wake re-evaluation on a wall-clock jump of more than 30 s (disk holds re-checked, network waits due;
    cool-downs, pauses and stopped queues kept).
- **Documentation:** logout, sleep and reboot are documented in `docs/architecture.md` §2.

### B2.11 — queues and priority (CORE-05)

- **Model:**
  - persistent queues with `main` always present;
  - existing jobs migrated into `main` in order (migration 6);
  - create, rename, limit (1–16), start, stop, delete (never deletes jobs or files; `main` refused; a target is
    needed when the queue has jobs);
  - membership, priority and manual order (`move` up/down/top/bottom).
- **Admission:** priority, then queue order, then manual position, then acceptance time, under the global 3 and each
  queue's limit. There is no preemption and the per-host budget is unchanged.
- **Stop/Start queue:** `queue_stopped` with checkpointed pauses; it never overrides a user pause, cancellation, disk
  hold or retry cool-down. It is restored after a restart.
- **Desktop:**
  - queues in the category panel, "(stopped)" in words;
  - queue views in execution order (column sorting stays presentational);
  - Start/Stop queue in the toolbar and Downloads menu;
  - Manage queues…; Queue and priority…; Move menu items and Alt+↑/↓;
  - en/bn catalogue.
- **CLI:** `queues`, `queue-create/start/stop/delete`, `set-queue`, `priority`, `move`.
