## 2. What works

### F07: Windows attachment safety

- **Order inside the existing journal:** intent → verified → placed → **attachment check** → complete.
- **At placement:**
  - the placed file's identity (volume serial plus file index; device plus inode on Unix) is recorded with `placed`;
  - the start of the check (`scan_started_ms`) is committed before the OS call.
- **The OS call:** `IAttachmentExecute::Save` runs on a dedicated thread in its own single-threaded COM apartment.
  - At most 2 run at once, never under the coordinator lock.
  - The call gets only the **sanitized origin** `scheme://host[:port]/`.
- **After it returns:**
  - the file is re-verified: it must exist, be the same file, and have the verified SHA-256;
  - **only then** is the outcome committed, with `complete`.
- **What the outcome means:**
  - `S_OK` with an intact file → `attachment_checked`, described as "processed… not removed or changed… not a
    malware verdict";
  - `INET_E_SECURITY_PROBLEM`, or a file missing, changed or replaced afterwards → `blocked` and the job fails
    with `SCAN_BLOCKED`. The file is never re-created or re-placed, and our own staging name of those bytes is
    removed;
  - any other error → `unavailable/service_error`, completed with a warning. On a volume with named streams,
    Downova writes Mark of the Web itself (`written_by_downova`), Chromium's precedent;
  - no result in 10 minutes → `unavailable/timed_out`, and the late result is discarded.
- **Mark of the Web** is written by Windows; Downova writes it only in the fallback above.
  - MOTW presence is reported as origin only, never as safety.
  - A volume without streams is reported as `unsupported_volume`.
- **SEC-03 is unchanged:** only `Save` is used; nothing is executed or opened.

### E06: the lifecycle states

- **The states:** `scanning`, `attachment_checked`, `blocked`, `unavailable` and `skipped`, with reasons.
- **Where they appear,** with the same values in the contract (`DownloadSnapshot.scan`), storage (`jobs.scan_json`),
  IPC and `dm get` (JSON and text):
  - the desktop list: "Complete (not checked)" for `unavailable` and `skipped`;
  - the details: a plain-language note per state, with an icon and a tone, never colour alone.
- **Checksum evidence (`verification`) stays separate.**
- **Downloads finished before this batch** have no scan record and show none: they are never presented as checked.
- **Cancel during a check is now allowed.**
  - The ticket is revoked, so a late result cannot complete or revive the job.
  - The file stays at its destination, recorded as `skipped/cancelled` ("not checked").
- **Restart during a check:** the file is re-verified, then checked again. A file that is missing or changed by
  then is `blocked/file_removed` or `blocked/file_changed`, and is never re-placed (the earlier journal rule re-placed
  missing files only when no check had started).
- **Notifications:** a single notice only after the durable outcome.
- **macOS and Linux:** `skipped/platform_not_supported`. The UI says "No malware check on this system" and never
  claims a Windows check.

### E05: diagnostics

- **`diagnostics.v1.preview`** builds an **allowlisted** report:
  - versions, build commit (CI builds), OS and architecture;
  - backend capabilities;
  - the attachment-check capability;
  - settings as values or counts;
  - job counts by phase, blocker and scan status;
  - up to 50 failures as `{job_id, phase, error kind, next action, scan status, age}`;
  - limitations;
  - an opt-in crash section: the last startup's recovery summary (Downova writes no crash dumps).
- **Bounds:** 200 jobs considered, 50 failures and 256 KiB. The lock is held only to copy the summary.
- **Redaction:**
  - the final text must pass `export_leaks` (header and parameter forms of credentials, URLs with
    userinfo/query/fragment, home-directory paths) or nothing is produced;
  - the preview keeps one snapshot.
- **`diagnostics.v1.export`** writes **exactly** that snapshot:
  - a synced temporary file in the target folder, then a no-overwrite hard link (or exclusive copy), or a rename
    when replace was confirmed;
  - typed errors for an existing file, a missing folder, a refusal (permission or read-only) and a full disk;
  - no temporary file is left behind.
- **Desktop:** Help → **Diagnostics…** previews in a read-only, labelled text box. The crash switch is off by
  default. **Save…** opens the native save dialog **in the shell (Rust)**, so the path never reaches the webview.
  - Double submits are guarded by a ref, and a stale preview answer is dropped.
- **CLI:** `dm diagnostics [--include-crash]` and `dm diagnostics-export <PATH> [--include-crash] [--replace]`.
  The export previews and exports through the same service code as the desktop.
- **Offline, no analytics:** nothing is transmitted.

### SEC-01 (this path)

- `marking_origin` keeps only scheme, host and port.
- `export_leaks` is the final check.
- The synthetic-secret test seeds userinfo, query, signature, path and fragment tokens; `Authorization`, `Bearer`,
  `Cookie` and `Proxy-Authorization` in an engine error; a proxy URL with credentials; a home path; and a queue
  name. It proves none of them reach the preview, the exported file or any event, and that useful facts remain.

## 3. Defects and design findings

- **A real false positive, found by the first run of the synthetic-secret test:**
  - the final check rejected the report because the limitation text says "no … cookies, headers";
  - fix: the check matches header and parameter forms (`cookie:`, `cookie=`, `authorization:`, `password=`…), not
    bare words;
  - a unit test pins both directions.
- **A process test's expectation changed by design:**
  - `f06` expected a cancel after placement to be refused;
  - with the check off the lock, on Windows the cancel arrives during `scanning` and is accepted, with the file
    intact and recorded as not checked;
  - macOS and Linux keep the old outcome;
  - the test now asserts per platform.
- **A boundary change (recorded in ADR 0026 and `docs/project-structure.md`):**
  - the workspace forbids `unsafe`; COM and Win32 calls need it, and no safe wrapper exists;
  - the new crate `dm-win-attachment` is the **only** crate allowed unsafe code: lint `deny`, `allow` only on the
    calling functions, SAFETY comments required;
  - `scripts/check-structure.mjs` now fails on unsafe code anywhere else, and on any other crate not inheriting the
    workspace lints.
