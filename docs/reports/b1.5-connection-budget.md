## Enforced limits and counting rules

| Limit | Where | Counts | Does not count |
|---|---|---|---|
| **3 active files** | `dm-service` `Core::admit` | jobs with a live attempt, desired `running`, not pending, not `verifying`, not disk-blocked, not cooling down | queued (`queue_limit`), paused, disk-blocked, retry cool-down, finalizing, finished |
| **8 connections per host** | `dm-backend-http` `limits.rs` (one budget per backend) | every request: probe, single transfer, resumed range, each segment worker, each redirect hop, from before it is sent until its response/body is dropped | idle pooled connections (none are kept) |
| 2–4 connections per large file | unchanged (B0.4.3) | ≥ 2 MiB, strong ETag, known length; at most 4 segments of ≥ 1 MiB | small or unsupported files use 1 |

Host key: lowercased host (punycode for IDN), trailing dot removed, IPv6 literal as written; **port and scheme ignored**.
Redirects: the previous hop's permit is released, then one is taken for the destination host. Admission order: oldest
first (creation time, then acceptance order; corrected in B1.6 from a job-ID tie-break). Admission never waits, and capacity is rebuilt from runtime state after a restart.

## Limitations and unverified cases

- The per-host guarantee counts Downova's open requests. The server's view includes a sub-100 ms teardown tail for
  dropped connections, which is measured, not hidden: the raw maxima are reported.
- The budget is per backend instance: other programs or a second service are not counted.
- No idle pool means a new connection (and TLS handshake) per request. The latency cost is not benchmarked. **No speed
  claim is made** (REL-04).
- Timeouts are covered through the failure path (C04), not by a stalled-server test.
- Retry cool-down and disk-full suspension are verified at coordinator level (cool-down) and by the B1.4 process tests
  (disk); there is no combined process test.
- aria2 is not limited by the HTTP limiter; its accounting is conservative (1 connection per file, ≤ 3 files).
- Limits are fixed: no settings, priorities or user queues yet (B2).

## Reproduction

1. Start a service:

   ```bash
   cargo run -p dm-service -- --data-dir /tmp/dv --download-dir /tmp/dv-dl
   ```

2. Add five large links: `cargo run -p dm-cli --quiet -- --data-dir /tmp/dv add <URL>` ×5.
3. `dm list` shows three transferring and two `queued` with `queue_limit`. As each finishes, the oldest waiting one
   starts.
4. Server side (one host, segmented files): no more than 8 concurrent connections, for example with `ss -tn` or
   `netstat -an` on the server.
