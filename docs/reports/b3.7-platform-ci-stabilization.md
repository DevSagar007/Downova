## 2. Root causes and fixes

| Failure | Cause | Category | Fix |
|---|---|---|---|
| detect test on macOS and Ubuntu 24.04 (actual `[]`, expected `[Native]`) | The simulated Windows locations were single strings with `\` separators (`r"Mozilla Firefox\firefox.exe"`). On macOS and Linux a backslash is a file-name character, so `join` looked for one file with that literal name. The fixture created real nested folders. On Windows `\` is the separator, so it passed there | product code (path construction); the fixture was correct | `windows_locations()` returns path components, joined with the host's separator. Real Windows paths are unchanged. New test `windows_locations_are_separator_free_components_found_on_every_host`: every family, every program directory; a folder with the executable's name is not an installation |
| a07 on Ubuntu 22.04 (no validated resume request) | A fixed 300 ms sleep before pausing. On a slow runner the TLS handshake and first chunks took longer, so the pause came before any resumable progress and the resume was a fresh GET without `If-Range`. (Pausing after completion was the other possible case.) | test timing (fixture coordination); no engine defect | Wait, bounded at 20 s, for a **durable checkpoint** with non-zero confirmed bytes. Pause, and assert the transfer is paused before completion. Every request after resume must have a non-zero `Range` start, `If-Range` and the session cookie. Exact length and SHA-256. The fixture is slower (20 ms per 16 KiB) so completion is about 5 s away |
| Linux smoke H2, H3, K7 (paused job `failed` after a restart; Resume stays failed) | The links have a query (`?slow=…&step=h`), which the service treats as protected and seals with the data key from the OS credential store (ADR 0027). The Linux smoke job had a D-Bus session but **no Secret Service**. The release service therefore had no data key, kept the protected part in memory only, and after the restart correctly reported `LINK_REFRESH_REQUIRED` (pause kept). Windows and macOS have real stores and passed | runner setup | `scripts/smoke/linux-secret-service.sh` starts gnome-keyring's secrets component inside the job's own D-Bus session (random per-run password). It proves the store with a store, lookup and clear round trip before the smoke runs, and fails explicitly if it is not usable. No smoke expectation was changed. No debug vault is used in release packages |

**Deterministic coverage of both credential-store cases** (service unit tests):
- `with_a_store_a_paused_protected_link_survives_a_restart_and_resumes`: with a working store, the paused job comes
  back paused with its 262144 bytes and transfers nothing on its own. Resume restores the unchanged sealed
  checkpoint with the full link. No secret is on disk.
- `without_a_store_a_paused_protected_link_needs_a_refresh_and_never_resumes_blind`: the manual pause is kept,
  with `LINK_REFRESH_REQUIRED` and next action Refresh link. Resume starts no transfer. No secret is on disk.

**Verification visibility:** `pnpm verify` now runs `cargo test --no-fail-fast`. Any failure still fails the step,
but every test binary runs, so one CI round shows all failures.
